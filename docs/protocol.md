# NTK protocol, v0.2

This is the contract between the keyboard, the relay, the enclave and every
verifier. Test vectors: `docs/test-vectors/text-v2.json` (text rule) and
`docs/test-vectors/crypto-v1.json` (sealing, request signature, a real stamp).
They are generated by `client/vectors.mjs`. The reference verifier is
`web/lib/ntk-verify.js`.

## Operations

The enclave's input is `{"operation", "auth", "sealed"}`.

| Operation | Auth | Sealed session | Result |
|---|---|---|---|
| `info` | no | no | keys, parameters |
| `enroll` | yes | yes | session folded into the fingerprint |
| `stamp` | yes | yes | `MATCH` with a signed stamp, or `NO_MATCH` |
| `status` | yes | no | counts only |
| `forget` | yes | no | fingerprint deleted |

Errors: `{"ok": false, "error": "<text>", "code": "<CODE>"}`. Codes are listed
in `enclave/src/enclave.rs`.

A stamp answer: `{"ok": true, "verdict": "MATCH", "id", "tag": "[NTK <id>]",
"stamp": {"id", "record", "sig", "pk"}, "detail"}`. A refusal: `{"ok": true,
"verdict": "NO_MATCH", "reason", "score_pct", "typed_pct", "taps"}`, where the
score is rounded down to a multiple of 5.

## Calling the enclave

Calls are paid by the project owner, so clients go through the relay, which
holds the payment key. Every call is asynchronous, because one call can take
from under a second to a few minutes.

Relay:

- `POST /api/call` with body `{"input": {...}}`. Answer: `{"call_id"}`.
- `GET /api/calls/<call_id>`. Answer: OutLayer's call object, unchanged:
  `{"status": "pending" | "running" | "completed" | "failed", "output", ...}`.
  `output` may be a JSON string; parse it when it is.
- `GET /api/info`. Answer: `{"output": <the enclave's info output>, "at": <ms>}`,
  cached by the relay.

Poll every 2 seconds, for up to 6 minutes. Do not resend an `enroll` or
`stamp` request after a timeout: the enclave refuses a replayed request. Sign
a fresh request instead.

Directly (tests and debug builds only): `POST {api}/call/nearthekeyboard.testnet/ntk`
with body `{"input": {...}, "async": true}` and header `X-Payment-Key`, then
`GET {api}/calls/<call_id>` with the same header.

## Session

What the keyboard seals: one typing session as UTF-8 JSON.

```json
{"v": 1, "layout": "qwerty-en-portrait-v1", "mode": "compose",
 "events": [{"k": "h", "d": 0, "u": 85, "x": 0.1, "y": -0.05}, {"ins": "pasted text"}]}
```

- `k`: what the key produced. Either one character (`"a"`, `"A"`, `" "`,
  `"\n"`), or a control key in angle brackets: `<bksp>`, `<shift>`, `<sym>`,
  `<enter>`, `<lang>`.
- `d`, `u`: touch down and touch up, in ms since the session started.
- `x`, `y`: the touch-down point minus the key's centre, as a fraction of the
  key's width and height (-1 to 1).
- `{"ins": "..."}`: text that entered the field without key taps.
- `mode`: `compose` or `copy`, on enrollment sessions only.
- `layout`: the keyboard layout and orientation.
- The enclave reads at most 20,000 events.

## Sealing

1. Make an ephemeral X25519 key pair `(esk, epk)`.
2. `shared = X25519(esk, transport_pk)`.
3. `key = HKDF-SHA256(ikm = shared, salt = epk || transport_pk, info = "ntk/v1/transport", length = 32)`.
4. `nonce` = 12 random bytes.
5. `ct = ChaCha20-Poly1305(key, nonce).encrypt(session JSON, aad = "ntk/v1|<op>|<account>")`.
6. `sealed = {"epk": hex(epk), "nonce": hex(nonce), "ct": base64(ct)}`, base64
   standard with padding.

`sealed_digest = hex(SHA-256(epk || nonce || ct))`.

## Request signature (NEP-413)

- `message` is the JSON string
  `{"ntk":1,"op":"<op>","account":"<account>","payload":"<sealed_digest or empty>","ts":<ms>}`.
  The exact string that was signed is sent.
- `ts` is the client's clock in ms. It must be within 10 minutes of the
  enclave's clock. For `enroll` and `stamp` it must also be greater than the
  account's last accepted `ts`, so a client keeps it increasing.
- `nonce` is 32 random bytes.
- `hash = SHA-256(u32le(2147484061) || u32le(len(message)) || message || nonce || u32le(len(recipient)) || recipient || 0x00)`.
- `signature = Ed25519(user secret key, hash)`.
- `auth = {"account_id", "public_key": "ed25519:<base58>", "signature": base64,
  "nonce": base64, "message", "recipient": "near-the-keyboard"}`.

The key must be the account's full-access key, or a function-call key whose
receiver is `nearthekeyboard.testnet`. An implicit account (64 hex characters)
is its own key.

## Stamp

The enclave signs `NTK-STAMP/v1\n` + the record JSON with the stamp key and
publishes `{"id", "record", "sig", "pk"}` under `stamp:<id>` in OutLayer's
public storage. Anyone can read it:

`GET https://testnet-api.outlayer.ai/public/storage/get?project=nearthekeyboard.testnet%2Fntk&key=stamp%3A<id>&format=raw`

A missing stamp answers 404.

- `id`: the first 10 hex characters of SHA-256(signature).
- Record v2: `{"v":2, "kind":"ntk-stamp", "account", "text_sha256",
  "text_chars", "taps", "typed_pct", "score_pct", "threshold_pct",
  "profile_sessions", "issued_at_ms", "project", "network", "call_id",
  "enclave"}`.
- `text_sha256` is the SHA-256 of the canonical text, UTF-8. `text_chars` is
  its length in Unicode scalar values.
- The enclave replays the keystrokes into the text itself. A stamp never
  carries the text.
- Version 1 records (stamps from before v0.2) hash the text with CR removed
  and surrounding whitespace trimmed, with no collapsing.

## Text rule v2

**Canonical text.** Every run of whitespace becomes one space (U+0020), and
whitespace at the start and the end is removed. Nothing else changes. No
Unicode normalization; letters keep their case.

Whitespace means exactly these code points (Unicode White_Space): U+0009 to
U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000 to U+200A, U+2028, U+2029,
U+202F, U+205F, U+3000. Implementations use this list, not their language's
own idea of whitespace: JavaScript's `\s` and Java's
`Character.isWhitespace` both differ from it.

**The tag.** `[NTK <id>]`, where `<id>` is 10 lowercase hex characters. The
keyboard inserts a space and the tag right after the text. Verifiers also
accept the older `[NTK @<account> <id>]`. Regular expression:
`\[NTK(?: @[^\s\]]+)? ([0-9a-f]{10})\]`.

**What a stamp covers.** The `text_chars` characters that stand right before
the tag, after the text before the tag is made canonical. A verifier:

1. takes everything before the tag in the same block of text, for example the
   post or the message the tag is in;
2. makes it canonical;
3. keeps its last `text_chars` scalar values;
4. compares their SHA-256 with `text_sha256`.

Text that stands earlier in the block (a name, an earlier sentence, an
earlier tag) is not covered and does not matter. For a v1 record, step 2 is
"remove CR, trim" instead.

**After a tag.** The keyboard starts a new session, so a later stamp in the
same field covers only what was typed after the earlier tag.

## Verdicts

| Verdict | Meaning |
|---|---|
| MATCH | Every check passed. |
| NO MATCH | A genuine stamp, but the text before the tag is not the text that was stamped. |
| INVALID | The stamp is not signed by the pinned key, or was altered. |
| UNKNOWN | No stamp has this id. |

The checks, in order: the stamp exists; its key is the pinned key; the
signature is valid; the id belongs to the signature; the record names the NTK
project; the covered text hashes to `text_sha256`.

A stamp says: this text was typed key by key on the NTK keyboard by someone
whose typing matches the fingerprint of this NEAR account. It does not say the
text was written without help.
